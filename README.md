# Форум-Фестиваль «Преображение» — сайт

Next.js 14 (App Router) + TypeScript + Tailwind CSS. Весь текстовый контент,
программа, цены и спикеры редактируются без изменения кода — через файлы
`/content/*.json` или встроенную административную панель `/admin`.

## 1. Быстрый старт

```bash
# 1. Клонирование репозитория
git clone <адрес вашего репозитория>
cd preobrazhenie-festival

# 2. Установка зависимостей
npm install

# 3. Создание файла переменных окружения
cp .env.example .env.local
# откройте .env.local и заполните значения (см. раздел 9)

# 4. Запуск проекта в режиме разработки
npm run dev
# сайт будет доступен на http://localhost:3000
# админ-панель — на http://localhost:3000/admin (пароль из ADMIN_PASSWORD)

# 5. Проверка сборки перед развёртыванием
npm run typecheck
npm run lint
npm run test
npm run build
```

## 2. Структура проекта

```
app/                    Страницы и API-маршруты (Next.js App Router)
  page.tsx              Главная страница (собирает все секции)
  admin/                Административная панель
  api/                  Серверные API-маршруты (формы, оплата, админка)
  oferta/, privacy/...  Юридические страницы
  payment/success|error Страницы результата оплаты
components/             React-компоненты (публичная часть + admin/)
content/                *** РЕДАКТИРУЕМЫЙ КОНТЕНТ САЙТА (JSON) ***
data/submissions/       Локальное хранилище заявок (если Supabase не подключён)
lib/                    Бизнес-логика: контент, валидация, оплата, хранилище, админ-сессия
supabase/schema.sql     SQL-схема для подключения Supabase
tests/                  Автоматические тесты (Vitest)
```

## 3. Как редактировать контент

Все тексты, даты, цены и программа хранятся в файлах `/content/*.json`.
Их можно редактировать двумя способами:

**А. Напрямую в репозитории** — откройте нужный файл, измените значения,
сохраните и запушьте в GitHub. Если сайт развёрнут на Vercel/Netlify,
изменения применятся автоматически при следующей сборке.

**Б. Через админ-панель `/admin`** (раздел «Контент сайта») — JSON-редактор
с сохранением по кнопке. Это удобно для быстрых правок в режиме разработки
(`npm run dev`) или на хостинге с постоянной файловой системой.

> **Важно про Vercel/Netlify:** serverless-функции этих платформ используют
> временную файловую систему — запись через `/admin` в файлы `/content`
> **не сохранится** между развёртываниями в продакшене. Для полноценного
> редактирования контента после публикации выберите один из вариантов:
> - подключите Supabase и перенесите контент в таблицу (потребует
>   небольшой доработки `lib/content.ts` — сейчас он читает JSON-файлы,
>   но структура данных уже готова для переноса в БД без изменения
>   компонентов);
> - подключите [Decap CMS](https://decapcms.org/) — бесплатную CMS,
>   которая редактирует те же JSON/Markdown файлы через коммиты в GitHub
>   (у Decap CMS есть готовый быстрый старт для Next.js);
> - используйте `/admin` только в режиме разработки, а готовые файлы
>   коммитьте в репозиторий вручную.

Файлы контента:

| Файл | Что в нём |
|---|---|
| `site.json` | Название, слоган, даты, место, ссылки, контакты, включение/выключение разделов |
| `program.json` | Программа по каждому дню (19–28 сентября) |
| `timing.json` | Базовый тайминг очной и онлайн-программы |
| `speakers.json` | Спикеры и учёные (карточки-заглушки «Спикер будет объявлен» по умолчанию) |
| `pricing.json` | Текстовый блок «Стоимость и проживание» |
| `packages.json` | Пакеты участия и их цены |
| `faq.json` | Частые вопросы |
| `practices.json` | Практики и мероприятия |
| `center.json` | Раздел «Центр Преображения» |
| `legal.json` | Реквизиты организатора для юридических страниц |

## 4. Административная панель

Откройте `/admin` и войдите с паролем из `ADMIN_PASSWORD` (файл `.env.local`).

**Обязательно смените `ADMIN_PASSWORD` и `ADMIN_SESSION_SECRET`** перед
публикацией сайта — значения по умолчанию в `.env.example` предназначены
только для тестирования.

Возможности панели:
- редактирование всех файлов контента (см. таблицу выше);
- просмотр заявок на участие, заявок спикеров, заявок партнёров и заказов;
- смена статуса заявки/заказа;
- экспорт любой таблицы заявок в CSV.

Механизм входа — подписанная HMAC-cookie (см. `lib/adminAuth.ts`), пароль
сравнивается на сервере timing-safe способом. Это простое, но реальное
решение для одного администратора. Если нужно несколько администраторов
с разными правами — подключите Supabase Auth (см. раздел 5) и замените
функции в `lib/adminAuth.ts` на вызовы `supabase.auth`, не меняя остальной
код `/admin`.

## 5. Подключение Supabase (база данных)

По умолчанию заявки и заказы сохраняются в локальные JSON-файлы
(`data/submissions/*.json`) — этого достаточно для тестирования, но не для
продакшена на serverless-хостинге.

1. Создайте проект на [supabase.com](https://supabase.com).
2. В SQL Editor выполните файл `supabase/schema.sql` из этого репозитория.
3. В настройках проекта скопируйте `Project URL` и `service_role` ключ.
4. Заполните в `.env.local` (и в переменных окружения хостинга):
   ```
   NEXT_PUBLIC_SUPABASE_URL=...
   SUPABASE_SERVICE_ROLE_KEY=...
   ```
5. Готово — `lib/storage.ts` автоматически начнёт писать заявки и заказы
   в Supabase вместо локальных файлов, без изменений в коде форм.

`SUPABASE_SERVICE_ROLE_KEY` — секретный ключ с полным доступом к базе.
Он используется **только на сервере** (в API-маршрутах) и никогда не
передаётся в браузer. Не публикуйте его.

## 6. Подключение оплаты (ЮKassa / CloudPayments)

По умолчанию `PAYMENT_PROVIDER=demo` — безопасный тестовый режим: оплата
считается пройденной сразу, без реального списания средств, страница
результата явно помечена «Демонстрационный режим». Это позволяет
проверить весь путь пользователя до подключения реального эквайринга.

### Подключение ЮKassa

1. Зарегистрируйте магазин на [yookassa.ru](https://yookassa.ru).
2. В личном кабинете получите `shopId` и секретный ключ.
3. В `.env.local` и на хостинге укажите:
   ```
   PAYMENT_PROVIDER=yookassa
   PAYMENT_SHOP_ID=...
   PAYMENT_SECRET_KEY=...
   ```
4. В личном кабинете ЮKassa укажите URL для уведомлений (webhook):
   `https://ваш-домен/api/payment/webhook`
5. Логика создания платежа и обработки webhook уже реализована в
   `lib/payment.ts` и `app/api/payment/*` — дополнительный код не требуется.

### Подключение CloudPayments

Задайте `PAYMENT_PROVIDER=cloudpayments`, `PAYMENT_SHOP_ID` (Public ID) и
`PAYMENT_SECRET_KEY` (API-секрет). CloudPayments обычно работает через
клиентский виджет Checkout.js — базовая заготовка заказа уже создаётся на
сервере (`lib/payment.ts`, функция `createCloudPaymentsPayment`), но вызов
виджета на странице оплаты нужно добавить дополнительно по документации
CloudPayments.

Секретные ключи **никогда** не попадают в клиентский код — вся работа с
платёжным провайдером происходит в серверных API-маршрутах.

## 7. Аналитика

Заполните в `.env.local`:
```
NEXT_PUBLIC_YANDEX_METRIKA_ID=...
NEXT_PUBLIC_GA_ID=...
```
Если переменные не заданы, счётчики просто не подключаются — ошибок не будет.

## 8. Развёртывание на Vercel / Netlify

### Vercel
1. Импортируйте репозиторий на [vercel.com/new](https://vercel.com/new).
2. Framework Preset определится автоматически как Next.js.
3. В Project Settings → Environment Variables добавьте все переменные из
   `.env.example` с реальными значениями.
4. Нажмите Deploy.

### Netlify
1. Импортируйте репозиторий на [app.netlify.com](https://app.netlify.com).
2. Build command: `npm run build`, Publish directory: `.next`
   (рекомендуется установить официальный плагин `@netlify/plugin-nextjs`,
   он подключается автоматически при выборе фреймворка Next.js).
3. В Site settings → Environment variables добавьте переменные из
   `.env.example`.
4. Задеплойте сайт.

## 9. Что нужно заполнить перед публикацией

- [ ] `ADMIN_PASSWORD`, `ADMIN_SESSION_SECRET` — сменить значения по умолчанию
- [ ] `content/legal.json` — реальные реквизиты организатора (ИНН, адрес,
      платёжные реквизиты, оператор персональных данных)
- [ ] `content/legal.json` → `refundPolicySummary` — реальные условия возврата
- [ ] `content/site.json` → `year`, `location.mapEmbedUrl`, контакты,
      ссылки на трансляцию
- [ ] `content/speakers.json` — заменить карточки-заглушки на подтверждённых
      спикеров по мере поступления заявок
- [ ] Переменные окружения оплаты (`PAYMENT_PROVIDER` и ключи), если нужен
      приём реальных платежей
- [ ] `NEXT_PUBLIC_SITE_URL` — реальный домен сайта
- [ ] Supabase (если нужно постоянное хранилище заявок в продакшене)

## 10. Известные ограничения

- Без подключённого Supabase запись заявок и правки через `/admin` работают
  только там, где файловая система постоянна (локальная разработка,
  сервер с постоянным диском). На Vercel/Netlify для продакшена
  настоятельно рекомендуется подключить Supabase (раздел 5).
- Отправка email-подтверждений участникам и уведомлений организатору
  помечена как `TODO` в `app/api/registration/route.ts` и
  `app/api/payment/webhook/route.ts` — добавьте вызов вашего email-провайдера
  (Resend, Postmark, SendGrid и т.п.), используя переменную `EMAIL_API_KEY`.
- Изображения (фото спикеров, обложка для соцсетей) по умолчанию не
  загружены — используются понятные текстовые заглушки. Значок сайта
  (favicon) и картинка для соцсетей генерируются автоматически кодом
  (`app/icon.tsx`, `app/opengraph-image.tsx`); замените их на собственную
  графику при желании.

## Обновление: новая визуальная концепция (v2)

Дизайн переработан под концепцию «космическое путешествие сквозь кристаллическую
мандалу к первозданной природе». Что добавилось поверх функциональности из
раздела выше:

- **Единый космический фон** на весь сайт — `components/visuals/CosmosBackground.tsx`
  (звёзды, Млечный Путь, кристаллическая мандала, световые волны). Управляется
  через `content/appearance.json` и вкладку **«Внешний вид»** в `/admin`.
- **Сакральные знаки** по одному на раздел — `components/visuals/SacredSigil.tsx`,
  назначение знаков редактируется в админке (`sectionSigils`).
- **Природное обрамление** (папоротники, камни, мох, капли) — `components/visuals/FernFrame.tsx`.
- **Композиционные шаблоны** разделов — `components/compositions/`:
  `ShellComposition` (раковина), `PyramidComposition` (две пирамиды),
  `MandalaComposition` (кристаллическая мандала).
- **Новые страницы**: `/online` (онлайн-трансляция) и `/gallery` (фотогалерея
  с категориями и полноэкранным просмотром). Контент — `content/online.json`
  и `content/gallery.json`, редактируется в общем JSON-редакторе `/admin`.
- **Вступительная заставка** (`components/IntroSplash.tsx`) — полноэкранное
  приглашение перед сайтом, с кнопкой «Пропустить» и запоминанием выбора
  (localStorage), не блокирует доступ к сайту.
- **Три уровня визуальных эффектов** (`полный / оптимизированный / минимальный`) —
  переключаются в `/admin` → «Внешний вид», применяются через атрибут
  `data-fx` на `<html>` и классы `.fx-heavy` / `.fx-medium` в `globals.css`.
- **Мягкое вертикальное перелистывание** — `scroll-snap-type: y proximity` на
  `<main>` (класс `.snap-book`) и `.snap-page` на каждой секции: секции слегка
  "прилипают" при скролле, но колесо мыши не перехватывается и свободная
  прокрутка не блокируется.

### Правдоподобие

На странице кемпинга и в галерее данные помечены как **«концептуальная
визуализация»**, пока организатор не загрузит реальные фотографии через
`content/gallery.json` (поле `imageType`) или `appearance.json` → `images`.
Сайт не создаёт фальшивых спикеров, партнёров, счётчиков участников или
отзывов — как и в исходном ТЗ.

### Известное упрощение

Полноценный drag-and-drop для порядка галереи и загрузка изображений через
интерфейс (а не по URL) в этой версии не реализованы — сейчас изображения
галереи и «Внешнего вида» задаются ссылками (URL) через JSON-редактор.
Добавление полноценной загрузки файлов потребует подключения Supabase Storage
(инфраструктура для этого уже есть — см. раздел 5 выше).
